# المرحلة 4 — الرجوع على أثر الرحلة
تاريخ الإنجاز: 2026-09-14.

## المنجز
- إضافة TrackNavigator مستقل لتحديد أقرب مقطع صالح ثم تتبع رؤوس المسار بالاتجاه العكسي بدل اختصار الرجوع إلى نقطة البداية.
- حساب الابتعاد عن المسار باستخدام المسافة إلى مقاطع الخط الفعلية، وليس عينة نقاط متباعدة فقط.
- تجاهل الوصلات بين مقاطع GPX المنفصلة وعدم حساب الفجوة كطريق صالح.
- BacktrackGuidance يعيد تحميل المسار خارج خيط الواجهة، ويعطي هدفًا متغيرًا لكل نقطة رجوع، ويعرض تحذيرًا عند عبور فاصل تسجيل.
- NavigationGuidance يدعم هدف رجوع مؤقتًا دون استبدال وجهة موقع محفوظة في SharedPreferences.
- استعادة followVehicle تلقائيًا عند بدء/استعادة الرجوع على الأثر.

## الاختبار والدليل
- أول تشغيل للبوابة: run 34845482075 فشل تجميعه لأن MapRuntimeBridge لم يكن يحوي resumeFollow؛ لم يدمج.
- أضيف resumeFollow ثم أعيد الاختبار على الالتزام 5b9159cd566a91a63c6741d4549a5099992799ca.
- GitHub Actions: Data Integrity Validation run 34845604030.
- النتيجة: نجاح compileDebugJavaWithJavac و testDebugUnitTest، بما فيها اختبارات منع اختصار المنعطف واستخدام مسافة المقطع وعدم وصل فجوة التسجيل.

## ما لم يختبر ميدانيًا
- مسار فعلي متقاطع أو شديد الانعطاف على شاشة T3.
- دقة حد الوصول 30م وحد تنبيه الابتعاد 120/180م في البر.

## الخطوة التالية
إصلاح مسارات الأزرار المحفوظة/الحفظ حتى لا تعترض MainActivity، توحيد محرر المواقع، ربط نتيجة إنهاء التسجيل الحقيقية بالواجهة، ومسح السرعة/التوجيه عند فقد GPS.
